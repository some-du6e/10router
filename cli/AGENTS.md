# CLI launcher rules

Paths are relative to the repo root.

| Rule | Enforcement |
| --- | --- |
| The launcher manages only the server child it spawned. Never kill a process found by name or by port. Before each start, `checkPortFree` refuses when anything answers on the dial address or the bind fails, and the launcher exits with a message saying what to do. | `cli/src/cli/utils/serverSupervisor.js`, `cli/src/cli/utils/serverProcess.js`; `tests/unit/cli-launcher-lifecycle.test.js` |
| The supervisor restarts a crashed server at most `MAX_RESTARTS` times (2, in `cli/src/cli/utils/serverSupervisor.js`): the third quick failure in a row ends the launcher. A run of `RESTART_RESET_MS` resets the count. `start()` never rejects. | `tests/unit/cli-launcher-lifecycle.test.js` ("launcher server supervisor") |
| Never signal a child that has exited: its PID may be reused. Every exit path, Ctrl+C in the raw-mode menu included, goes through `killServer`. | `killServer` in `cli/src/cli/utils/serverProcess.js`, `interrupt` in `cli/src/cli/utils/input.js`; `tests/unit/cli-launcher-lifecycle.test.js` ("stopping our own server") |
| One launcher per DATA_DIR. `<DATA_DIR>/launcher.lock` holds the holder's PID and process start time, is created by hard-linking a fully written temp file, and a stale one is renamed aside and re-checked before removal. A holder whose start time can't be read is retried for 12 s, then refused unless its lock predates this boot; that takeover is bound to the exact lock content whose age was checked. A launcher re-checks that the lock still holds its content before every server start. `killAppProcesses` removes the lock when it kills that launcher. | `cli/src/cli/utils/dataDirLock.js`, `src/lib/appProcesses.js`; `tests/unit/cli-data-dir-lock.test.js`, `tests/unit/app-updater-kill-sweep.test.js` |
| Readiness means our own child is alive and its `/api/health` answers a fresh challenge with HMAC-SHA256(launch nonce, challenge\|peer host\|peer port\|salt). The peer is the connection custom-server.js stamped (`x-9r-real-ip`, `x-9r-real-port`), which the launcher checks against its own socket, so a relayed answer fails. The nonce goes to the child in `TENROUTER_LAUNCH_NONCE` and custom-server.js removes it from the env at boot. The API client gate (`createReadinessGate`, `pauseUntil`) is closed from each child's exit until the next child passes, so no request, CLI token included, goes out in between. It gives up after 120 s with a message. | `cli/src/cli/utils/serverProcess.js`, `custom-server.js`, `src/lib/launchProof.js`, `src/app/api/health/route.js`, `cli/src/cli/api/client.js`; `tests/unit/launch-proof.test.js`, `tests/unit/cli-launcher-lifecycle.test.js` |
| The Windows/Linux tray relaunch carries `--host` and `--port` (`getBackgroundArgs`). Autostart entries carry them too, and also set `DATA_DIR` and `TENROUTER_AUTOSTART=1`. `enableAutoStart` never runs `launchctl`. `--host` and `--port` are validated once, at parse time. A DATA_DIR from an autostart entry must be owned by the user and not group/other-writable, checked before the npm self-heal runs in it. | `cli/src/cli/utils/launchArgs.js`, `cli/src/cli/tray/autostart.js`, `cli/cli.js`; `tests/unit/cli-autostart-bind.test.js`, `tests/unit/cli-data-dir-lock.test.js`, `tests/unit/cli-launcher-lifecycle.test.js` |
| The dashboard update relaunch keeps the bind only when the launcher in the env is the server's parent and HOSTNAME passes the same host check. | `src/lib/appUpdater.js`; `tests/unit/app-updater-relaunch.test.js` |
| Server stdout and stderr are piped and decoded as UTF-8 streams: only the setup-token banner reaches the terminal (and stays in the menu header until setup consumes the token or it expires), everything else goes to the crash log. On Linux tray and autostart runs, and on macOS when stdout or stderr is an old `/tmp/10router*.log` (or that path is a symlink, which launchd follows), the banner stays out of stdout and the launcher points to `setup-token.json` instead. `--log` shows all of it. | `attachServerOutput`, `bannerToStdout` in `cli/src/cli/utils/launchArgs.js`, `writesToLegacyLog` in `cli/src/cli/tray/autostart.js`; `tests/unit/cli-launcher-lifecycle.test.js` ("server output"), `tests/unit/cli-autostart-bind.test.js` |

Run from `tests/` with `./node_modules/.bin/vitest run unit/cli-launcher-lifecycle.test.js unit/cli-data-dir-lock.test.js unit/cli-autostart-bind.test.js unit/launch-proof.test.js unit/app-updater-relaunch.test.js unit/app-updater-kill-sweep.test.js`. CI runs all of them in `.github/workflows/security-local-host.yml`.
